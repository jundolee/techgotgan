## 전략

테크곳간을 단순히 “기술 블로그를 모아둔 곳”으로 알리는 대신, 매일 쌓이는 기업 사례 중 **문제–해결–결과가 선명한 글을 골라 빠르게 소개하고 원문까지 연결하는 곳**으로 홍보한다.

- **대상:** 제품·서비스·운영을 개선하는 일을 하거나, 다른 팀의 실제 해결 사례를 통해 아이디어를 얻고 싶은 실무자. 개발자로 한정하지 않는다.
- **방문 트리거:** “우리도 비슷한 문제를 겪는데, 다른 팀은 어떻게 풀었지?”
- **약속:** 회사가 실제로 겪은 문제, 선택한 해결 방법, 공개된 결과를 짧게 훑고 관심이 생기면 원문과 관련 사례를 이어서 읽을 수 있다.
- **홍보 방식:** 매일 수집된 글을 모두 알리지 않는다. 주 2~3편을 편집 기준으로 골라 독립적으로 유용한 사례 소개로 배포한다.

## 선정 기준

아래 항목을 모두 확인할 수 있는 사례만 소개한다.

1. 당사자가 겪은 구체적인 문제나 제약
2. 문제를 해결하기 위해 실제로 한 선택이나 변경
3. 결과를 뒷받침하는 공개된 수치 또는 구체적 변화

수치와 효과는 출처가 공개한 범위 안에서만 표현하고, 회사가 발표한 결과임을 드러낸다. 결과가 없는 글은 해결 과정 소개로만 다룬다. 요약 문안은 테크곳간의 편집 소개이지 원문 전체를 대신하지 않으며, 원문 링크를 함께 둔다.

## 판단 기준

각 게시물에서 다음 단계를 따로 본다.

1. 게시물 도달과 외부 링크 클릭
2. UTM으로 확인된 테크곳간 랜딩 세션
3. 기사 미리보기 열기(`article_click`)와 원문 이동(`source_article_click`)
4. 공유 유입 및 7일 재방문

가입은 필수 행동으로 두지 않는다. 링크 클릭이나 기사 열람이 적으면 게시 채널·첫 문장·사례의 관련성을 순서대로 점검한다. 랜딩은 있지만 원문 이동이 적으면 요약이 이해되는지, 소개한 결과가 원문과 맞는지 살펴본다. 캠페인별 랜딩 고유 사용자가 30명 미만이면 성공·실패를 선언하지 않고 방향성만 기록한다.

- 뱅크샐러드: 우리 팀의 반복 업무 가운데 자동화해볼 수 있는 것은 무엇인가?
- 컬리: 우리 서비스에서 변경 뒤 확인할 테스트가 빠진 화면은 어디인가?
- 네이버 D2: 오탈자나 별칭으로 검색해도 사용자가 원하는 대상을 찾을 수 있는가?
- 모바일은 기본 공유 시트를, 데스크톱은 질문과 사례 링크 복사를 제공한다. 수집 이벤트에는 질문 문장이나 기사 제목을 넣지 않는다.
- 수신 링크는 `utm_source=techgotgan`, `utm_medium=team_prompt`와 사례별 `problem_case_prompt_*_2026w46` 캠페인을 사용한다. `share_action_completed`의 `share_surface=case_collection`, 수신자의 UTM 방문, 기사 열기, 원문 이동을 각각 확인한다.
- 배포: PR #221이 `42dfaec81d4382a4bec0de95056d381b7a66d842`로 병합됐다. Vercel Production 배포 `A49ME5M1GHN8rTrBtLcVt4zzF6ri`가 `Ready`이며 `/cases`는 1440px·390px에서 문제없이 표시된다.
- 공유 QA: 각 카드의 질문과 `회의 질문 공유` 버튼을 데스크톱·모바일에서 확인했다. 브라우저가 네이티브 공유를 지원해 QA 중 공유 시트나 복사 기능은 실행하지 않았다. 공유 성과는 아직 없다.
- 배포/성과 판정은 별도 기록한다. 공유 동작 클릭만으로 외부 도달이나 유입 성공으로 계산하지 않는다.

### 다음 유입 가설: 문제에서 사례 찾기

‘기술 분야’를 먼저 고르게 하지 않고, 방문자가 해결하려는 일에 가까운 표현으로 사례에 바로 진입하게 한다. `/cases`에 반복 업무 줄이기·실수 줄이기·검색 결과 개선의 세 선택지를 두고 각 사례로 이동시킨다.

- 선택은 고정된 `problem_kind` 값(`workflow_automation`, `quality_checks`, `search_experience`)만 Amplitude에 기록한다. 검색어, 자유 입력, 기사 제목은 보내지 않는다.
- 방문자는 로그인 없이 해당 사례 카드와 팀 질문까지 바로 볼 수 있다.
- 측정은 `case_problem_selected` → `article_click` → `source_article_click` 및 공유 UTM 방문으로 나눈다. 선택 수만으로 유입 성공으로 보지 않는다.
- 배포: PR #223이 `31a916aa842d304951f54ffde98d1849fb363366`로 병합됐다. Vercel Production 배포 `CDweAGNn2iPyf8sgsfsPHusckCG3`가 `Ready`다.
- Production QA: 캐시 우회 새 탭에서 1440px·390px 모두 질문 제목 1개와 세 선택지 3개가 사례 카드 위에 표시되는 것을 확인했다. 선택을 클릭하지 않아 QA 이벤트는 만들지 않았다.
- 현재 성과 상태: `case_problem_selected`는 Production에 배포됐지만 아직 실제 선택/UTM 유입 결과는 관찰되지 않았다.
