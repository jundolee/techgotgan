## 현재 기준선

2026-10-29에 GA4 `Techgotgan` 속성에서 확인한 최근 28일(2026-10-01~10-28) 전체 사이트 수치:

- 활성 사용자 162명, 신규 사용자 159명
- 활성 사용자당 평균 참여 시간 3분 14초
- 이벤트 3.4천 건

이 수치는 전체 사이트 기준이며, 기업 가이드별 수치나 채널별 성과는 아니다. 실험 결과와 직접 비교하는 분모로 쓰지 않는다. 현재 수치로는 유입 대부분이 신규 사용자이고, 새로운 유입 경로를 찾는 일이 우선이라는 정도만 알 수 있다.

같은 사전 기간의 채널 확인:

- GA4 첫 사용자 소스/매체에서 `okky / community`는 활성 사용자 27명, 세션 소스/매체에서는 세션 36건으로 식별 가능한 커뮤니티 중 가장 컸다. 이는 10월 1~28일의 실험 전 수치다.
- GitHub 저장소는 공개 상태지만 Traffic API의 최근 14일(10월 14~27일) 저장소 방문이 0회, 순방문이 0회였다. 이는 저장소 페이지 조회 지표이며 README 링크 클릭 수와 동일하지 않다.
- Search Console URL 검사는 가이드가 Google에 색인되어 검색결과에 표시될 수 있다고 확인했다. 다만 정확한 URL로 필터한 최근 7일(10월 20~26일) 검색 성과는 클릭 0회·노출 0회였다. 같은 기간 도메인 전체는 클릭 1회·노출 66회·CTR 1.5%·평균 게재순위 8.2였고, 보고서 마지막 업데이트는 점검 시각 기준 6.5시간 전이었다. 두 수치 모두 실험 시작 전이다.
- OKKY에 바로 게시하지 않는다. [현재 공개된 운영정책](https://okky.kr/policies/operation-policy)은 승인받지 않은 외부 플랫폼 연결과 상업적 게시물을 제한한다. 게시가 필요하면 정책 최신 여부와 허용 형식을 먼저 확인한다.

## 배포·측정 준비

- 가이드 페이지는 이미 Production에서 열리는 것을 확인했다.
- PR #94가 `238370fb887094ba529b5a74930abccc08335908`로 병합됐고 Vercel Production 상태는 `Deployment has completed`였다. 2026-10-29 01:52:06 UTC에 병합됐다.
- 서비스 배포는 01:52 UTC에 완료됐지만, 첫 유입 캠페인 게시 전이므로 03:26 UTC까지의 확인·QA 방문은 실험 성과에서 제외한다.
- GitHub README 링크에는 `utm_source=github&utm_medium=readme&utm_campaign=career_guide_toss_frontend`가 붙어 있다.
- 가이드 상단에 공유 버튼을 두었다. 공유 링크에는 `utm_source=techgotgan&utm_medium=share&utm_campaign=career_guide_toss_frontend_2026q4`가 붙고, Amplitude에는 완료한 공유 방식과 `career_guide` 화면 유형만 전송한다.
- 원문 이동은 `career_guide_interaction` 이벤트의 `action=source_click`, `detail=chapter|knowledge|interview|careers`로 본다. 익명 피드백은 `action=feedback`, `detail=helpful|not_helpful`이다.
- GA4에서 랜딩 경로와 `Session source / medium`, `Session campaign`을 확인한다. Amplitude에서 `page_viewed`의 `/careers/toss-frontend`, 원문 클릭, 피드백, 공유 완료 이벤트를 확인한다.
- Amplitude 저장 차트: [Techgotgan 2주 실험 - 가이드 방문 및 행동](https://app.amplitude.com/analytics/solitary-sun-768076/chart/mz4utw3o). `page_viewed`는 `page_path=/careers/toss-frontend`, `career_guide_interaction`은 `guide=toss_frontend`로 각각 필터링해 고유 사용자를 본다. 저장 차트의 일별 기간은 2026-10-29~2026-11-12(UTC)다.
- 링크를 직접 열어 검수한 운영자 방문은 결과에서 제외하거나 별도 메모한다.

## 리포트 확인 주기

- GA4와 Amplitude는 **48시간마다** 확인한다. 첫 외부 배포를 기준으로 다음 정기 확인은 2026-10-31 03:26 UTC(한국시간 12:26)로 잡는다.
- Search Console은 반영 지연이 있어 **주 1회** 확인한다. 보고서의 최종 업데이트 시각과 데이터 종료일을 함께 기록한다.
- 정기 주기와 별도로 8일차 중간 점검(2026-11-05)과 14일차 최종 평가(2026-11-12 03:26 UTC)를 한다.
- 실시간 보고서에서 QA/운영자 방문과 실제 유입을 구분할 수 없으면 성과로 계산하지 않고 메모한다.

## 판정 기준

- **최소 관찰선:** 14일 동안 테스트 방문을 제외한 랜딩 고유 방문자 30명. 30명 미만이면 판정 유보이며, 채널 배포 부족과 랜딩 전환 부족을 구분한다.
- **유입 신호:** source/medium이 식별되는 외부 방문이 발생하고, 어느 채널에서 왔는지 확인할 수 있다.
- **가치 신호:** 방문자 중 원문 자료를 연 비율과 피드백 내용을 함께 본다. 클릭은 관심 신호이지 취업 준비에 도움이 됐다는 증명은 아니다.
- **공유 신호:** 공유 완료 이벤트와 `utm_medium=share`로 유입된 세션을 따로 본다. 공유 버튼 클릭 수만으로 바이럴이라고 판단하지 않는다.
- **후속 결정:** 유입이 있되 원문 클릭이 적으면 랜딩의 대상/선별 기준/자료 설명을 고친다. 특정 채널만 유입을 만든다면 다음 실험에서 그 채널을 집중한다. 30명 미만이면 PMF나 랜딩 실패로 판단하지 않고 배포 채널과 기간을 보완한다.
