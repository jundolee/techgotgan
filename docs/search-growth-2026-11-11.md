# 검색 유입 개선: 문제 해결 가이드

## 확인한 기준선

2026-11-11 Search Console의 최종 갱신 표시는 3.5시간 전이었고, 실제 차트 날짜는 2026-10-20~11-08이었다. 도메인 전체 클릭 10회, 노출 271회, CTR 3.7%, 평균 게재순위 9.6이었다. 한국은 클릭 10회·노출 192회였다. 검색어 표에 보이는 상위 행은 회사·발행처명 중심이다. 익명화된 검색어가 있어 공개 쿼리 행을 전체 수요로 간주하지 않는다.

`/blogs`는 같은 기간 61노출·1클릭·CTR 1.6%·평균 순위 8.5였다. 해당 페이지의 제목·설명은 PR #227에서 이미 변경했고 재수집 요청도 접수됐다. 이번 작업에서 같은 문안을 다시 바꾸지 않는다. 3개월 필터를 선택해도 실제 차트 날짜가 바뀌지 않아 기간별 추이 비교는 검증되지 않았다.

## 이번 검색 가설

기술명이나 발행처명으로 찾는 목록에 더해, 구체적인 문제를 검색한 사람이 검토 순서와 양식을 얻는 페이지를 만든다. 검색량과 상위 노출이 검증된 키워드라는 뜻은 아니다. 두 주제는 공개 원문에서 과정과 결과를 확인할 수 있고, 기존 `/cases`와 주제 허브에서 실제 독자에게 연결할 수 있어 선정했다.

| 페이지 | 대응할 질문 | 독자에게 제공하는 것 |
|---|---|---|
| `/guides/e2e-test-coverage` | E2E 테스트에서 빠진 화면을 어떻게 찾는가? | 화면과 사용자 행동을 구분하는 검토 순서, 빈 화면 인벤토리 CSV |
| `/guides/ai-workflow-automation` | AI 업무 자동화는 어떤 작업부터 시작하는가? | 데이터·환경·담당자·시간 비교 체크리스트, 빈 후보 검토 CSV |
| `/guides/product-search-for-planners` | 검색 기능을 기획할 때 어떤 조건을 확인하는가? | 기존 네이버 D2 사례와 다섯 가지 제품 검토 질문 |
| `/guides` | 문제에 맞는 가이드를 어떻게 찾는가? | 위 세 페이지를 연결하는 공개 디렉터리 |

신규 두 가이드는 컬리·뱅크샐러드 원문의 사실과 테크곳간의 검토 제안을 구분한다. 구현을 직접 해본 것처럼 서술하지 않는다. 결과 수치에는 해당 회사의 조건을 붙이고, Playwright·n8n 공식 문서를 연결한다. 저작물 원문 전체를 복제하지 않는다. 기존 기사 상세의 색인 정책은 유지한다.

홈·둘러보기·푸터, `/cases`의 각 사례, 관련 주제·기술 허브에서 연결한다. 두 신규 페이지는 정적으로 생성하고 자체 canonical, 설명, Article/BreadcrumbList와 출처를 제공한다. sitemap에 가이드 디렉터리와 두 페이지를 추가하고 실제 수정한 본문의 lastmod를 갱신한다.

## 검증과 후속 측정

- 로컬 build 통과. 기존 테스트 20개 통과. lint 오류 0개, 기존 `_email` 미사용 경고 1개.
- 실제 HTTP 응답에서 가이드 4개 경로의 200, 단일 H1, 자체 canonical, indexable robots, 설명을 확인했다. 신규 페이지의 JSON-LD 출처·표·목차 대상·CSV 응답과 UTF-8 BOM을 확인했다. 잘못된 slug는 404이며 기존 고정 경로는 그대로 열린다.
- Aside에서 화면 인벤토리 CSV의 실제 다운로드를 확인했다. 1440/1024/768/390px의 document overflow를 점검했다. 긴 페이지의 fullPage 캡처가 같은 뷰포트를 반복해 붙이는 현상이 있어 전체 페이지 시각 검증 자료로 사용하지 않는다. 뷰포트별 상단과 목차 이동 후 표를 별도로 확인한다.

배포는 검색 성과가 아니다. 배포 URL·실제 Production·Google 색인 상태는 아래 실행 기록에 따로 남긴다.

2026-11-18부터 Search Console의 실제 최신 날짜를 확인해 `/guides/` 페이지별 첫 노출과 검색어를 관찰한다. 2026-12-09 이후에는 기간이 온전히 포함된 28일 데이터에서 한국·웹 검색의 비브랜드 문제 검색어, 노출, 클릭, CTR, 같은 검색어의 순위를 비교한다. 표본이 작을 때 CTR 변화나 순위 상승을 성공으로 단정하지 않는다.

자연검색 랜딩 이후 `source_article_click`의 `editorial_guide` 표면과 재방문을 함께 본다. QA 출처는 실제 사용자에서 제외한다. 새 이벤트를 만들거나 테스트 로그인을 전환 성과로 세지 않는다. 회사 연락·제휴 제안은 사용자 제한에 따라 진행하지 않는다.

## 2026-11-11 기술 허브 관련성 점검

Search Console의 “크롤링됨 - 현재 색인이 생성되지 않음” 예시에는 Spark·Cloud·LLM·Kafka 허브가 포함돼 있었다. Google이 색인을 보류한 정확한 이유는 보고되지 않았다. 다만 Production Spark 허브의 첫 글은 Apache Spark가 아닌 `Muse Spark Open`이었고, `Gemini Spark` 제품 소식도 섞여 있었다. Go·Swift·SQL 허브에는 제목과 무관하게 발췌에서 기술명이 언급된 뉴스·일반 글이 앞쪽에 있었다.

Go·Swift·Spark·AI 에이전트·SQL처럼 넓게 쓰이는 기술명은 기사 제목에서도 그 주제가 드러나야 해당 허브에 넣는다. Spark 이름을 쓰는 Muse·Gemini 제품 소식은 제외한다. 나머지 기술은 본문 발췌 매칭을 유지해 DaaS·클라우드 전환처럼 제목만으로 설명하기 어려운 구현 글을 지우지 않는다. 변경한 허브와 기술 디렉터리의 sitemap `lastmod`를 실제 수정 시각으로 갱신한다.

배포 전, 공개되어 있던 첫 20건에 새 규칙을 대입한 표본에서 Spark 10/16, Go 10/20, Swift 9/14, AI 에이전트 16/20, SQL 8/20건이 남았다. 모두 인덱싱 최소 기준 3건 이상이었다. 이 표본은 전체 후보 풀이 아니므로, Preview/Production에서 실제 렌더링·개수·관련성을 다시 확인한다. Google의 재크롤링과 색인 결정은 이후 별도 관찰한다.
