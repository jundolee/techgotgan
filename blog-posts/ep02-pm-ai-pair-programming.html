비개발자 PM의 AI 메이커 도전기 #2

코드 한 줄 못 쓰는 기획자가 AI를 페어 프로그래머로 썼더니

"에러 복사-붙여넣기 30번 끝에 localhost:3000에 띄운 나만의 첫 피드"

지난 1편에서는 매일 아침 업데이트도 없는 기술 블로그들을 하나씩 순회하던 피로감과, 결국 직접 나만의 테크 피드 리더기를 만들어보기로 마음먹은 이야기를 적었습니다.

마음을 먹은 당일 저녁, 곧바로 노트북을 열었습니다. 기획서 쓰는 건 익숙하니 AI 에이전트한테 만들고 싶은 걸 말하면 금방 완성될 줄 알았습니다.

하지만 막상 시작하자마자 첫 화면을 보기도 전에 막히고 말았습니다.

기획자 생각엔 화면 하나 만들고 블로그 RSS 주소들을 긁어와 피드로 띄우면 끝날 일 같았는데, 현실은 터미널, Node.js, Git, zsh, npm 같은 낯선 개발 환경 설정부터 마주해야 했습니다.

코드는 몰라도 요구사항은 정리할 수 있으니까

평소 피그마로 화면을 그리고 노션에 요구사항(PRD)만 작성해오던 기획자에게 터미널 명령어와 개발 환경 설정은 여전히 낯선 영역이었습니다. 주변 동료 개발자에게 물어볼 수도 없는 개인 프로젝트였기에, 기댈 곳은 AI 에이전트뿐이었습니다.

그때 문득 코드를 직접 짜진 못해도 만들고자 하는 스펙을 명확하게 정리하는 건 기획자가 가장 잘하는 일이라는 생각이 들었습니다.

그래서 평소 개발팀과 협업할 때처럼 만들고자 하는 기능과 화면, 제약 조건을 정리해 AI에게 프롬프트로 전달했습니다.

[요구사항 정리]
1. Next.js App Router 기반으로 테크 블로그 리더기 구성
2. 토스, 당근, 배민, 카카오 등 국내 주요 기업 테크 블로그 RSS 30개 목록 관리
3. 크론(Cron)을 활용해 새 글을 자동 수집하고 발행일 최신순으로 정렬
4. 출근길에 제목과 썸네일을 빠르게 훑어볼 수 있는 깔끔한 카드형 피드 UI

프롬프트를 입력하자 AI는 프로젝트 기본 셋업부터 RSS 수집 로직, 화면 컴포넌트 코드까지 순식간에 작성해 내려갔습니다. 이때까지만 해도 오늘 안에 바로 배포까지 할 수 있겠다는 기대감이 들었습니다.

터미널에 쏟아진 에러와 반복된 디버깅

하지만 생각처럼 한 번에 돌아갈 리 없었습니다.

AI가 안내해 준 대로 터미널에 npm run dev를 실행하자마자 긴 에러 로그가 화면을 채웠습니다.

Module not found: Can't resolve 'feed'
Unhandled Runtime Error: Hydration failed...
Access to fetch has been blocked by CORS policy...

터미널 앞에서 까만 창을 마주했을 때의 솔직한 심정

Hydration 오류나 CORS 정책 같은 키워드는 기획 업무를 하면서 말로만 들어봤지, 로컬 환경에서 직접 맞닥뜨리니 어디서부터 손을 대야 할지 막막했습니다.

이때 비개발자인 제가 할 수 있는 최선의 방법은 에러 메시지를 그대로 복사해 AI에게 다시 질문하는 것이었습니다.

"방금 코드를 넣고 실행했는데 이 에러가 발생했어. 원인과 해결 방법을 단계별로 알려줘."라며 로그를 그대로 전달했습니다.

AI는 패키지 버전 의존성 문제나 서버/클라이언트 컴포넌트 간의 렌더링 차이를 설명하며 수정된 설정과 코드를 제시해 주었습니다.

에러 로그를 복사해 질문하고, AI가 제안한 코드를 반영해 다시 실행해보는 과정을 수십 번 반복했습니다.

localhost:3000에 화면이 뜬 순간

긴 씨름 끝에 마침내 터미널에 정상 실행 메시지가 나타났습니다.

✓ Ready in 2.1s (compiled 148 modules)
✓ Local: http://localhost:3000

브라우저 주소창에 localhost:3000을 입력하자, 설정해 둔 토스, 당근, 배민 등의 최신 기술 블로그 글들이 깔끔한 카드 피드로 화면에 표시되었습니다.

실제로 화면이 정상 동작했을 때의 순간

개발 지식이 깊지 않아도 문제를 명확히 쪼개고 AI에게 구체적으로 질의하면 실제로 동작하는 프로덕트를 구현할 수 있다는 것을 체감한 순간이었습니다.

곧바로 Vercel을 통해 호스팅까지 진행했습니다. 모바일 브라우저에서도 접근할 수 있는 나만의 웹 주소가 생겼고, 다음 날 출근길 지하철에서 실제로 이 피드를 열어보았습니다. 이전처럼 블로그들을 일일이 돌아보지 않고도 새 글을 한자리에서 확인할 수 있게 되었습니다.

"혼자 쓰기엔 아까운데?"라는 생각의 시작

며칠 동안 출근길에 직접 만든 리더기를 사용해 보니, 매일 아침 북마크를 뒤적이던 번거로움이 확실히 줄어들었습니다.

실제로 써보며 유용함을 체감하자 자연스럽게 욕심이 생겼습니다.

"나 혼자만 쓸 게 아니라, 나와 비슷한 고민을 하는 다른 기획자나 개발자 동료들에게도 공유하면 좋지 않을까?"

"기왕 만드는 김에 글 간의 연관 지식을 연결해 주는 제텔카스텐(Zettelkasten) 기능까지 붙여서 제대로 된 서비스로 만들어보면 어떨까?"

하지만 개인용 토이 프로젝트를 불특정 다수가 쓰는 공개 서비스로 전환하는 일은 완전히 다른 이야기였습니다. 이때 시작된 기능 욕심은 머지않아 서비스 운영과 아키텍처 전반에 걸친 크고 작은 난관으로 이어지게 됩니다.

국내 주요 기업 테크 블로그 최신 글을 한곳에서 모아보기

아침마다 여러 기업의 기술 블로그를 일일이 찾아다니는 불편을 줄이고자 만든 '테크곳간'을 운영하고 있습니다.
토스, 당근, 배민, 카카오 등 100여 개 기업 블로그의 새 글을 한자리에서 확인하실 수 있습니다.

  • 가입 없이 바로 확인: 별도 회원가입 없이 접속 즉시 최신 기술 글 피드를 탐색할 수 있습니다.
  • 업데이트 있는 글만 선별: 오랫동안 글이 올라오지 않는 블로그는 제외하고, 최근 발행된 글 위주로 모아봅니다.
  • 연관 글 자동 추천: 지금 읽는 글과 맥락이 이어지는 다른 기업의 관련 글들을 자동으로 추천해 줍니다.
